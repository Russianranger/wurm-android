# 0.10.14: align the local login credential with the authenticated identity

## What the 0.10.13 Thor reports establish

The supplied `wurm-server-report(3).txt` and `wurm-client-report(8).txt` use
0.10.13's `loginbase64` package for both processes. The server session is
`session-68400986-4c68-4d34-9ae1-acd3dea958a5`.

- The position and login overlays are active. The login class SHA-256 is
  `dd8fdfd33193db33e4d1203039b4c2112be27036eeb93a05064fd845772b8695`.
- `BASE64_ENCODE_ACTIVE inputBytes=20 outputChars=28` proves the encoder is used
  during this real login attempt; the previous missing-class failure is gone.
- At **17:44:34.809924829 UTC**, LoginHandler reports an **authenticated** user
  attempting login with incorrect credentials from `/127.0.0.1`.
- The server remains alive until the user's shutdown; exit zero is recorded at
  **17:45:11.132070 UTC** with shutdown requested.
- The client reports `login-denied: You need to be authenticated`, closes the
  window after nine frames, and then exits with SIGABRT/134. Its matching native
  crash identifies Scudo heap corruption during `libEGL.so` FileBlobCache/cache
  destruction through process exit. This follows the login rejection; it does
  not explain the server's credential mismatch. The original corruption source
  remains unknown. Serial GC is still selected, not proven a permanent fix.

## Verified credential contract and minimal correction

Inspection was local, against the user's legally supplied server JAR:
`9ea2761f210e05e7080777e988ddc0bd04e6fa5221813cdf141881cfb8ec8e06`.
No game class, disassembly or patched proprietary JAR is committed or bundled.

The server's offline ticket path records the identity as authenticated and sends
acceptance. The ordinary login packet separately contains player name, login
credential, server password and identity. `LoginHandler.login` hashes the received
credential with a salt derived from the normalized player name. `handleLogin`
hashes the identity with the same salt, checks prior authentication, then compares
the two hashes. Its two rejection branches share the client-facing message, but
the server log distinguishes them. This report matches the branch after successful
authentication: the hashes differ. The server password is checked afterward.

Our direct launcher had set the real engine's login password to an empty string.
It now calls the existing `LocalSession.identity()` and passes that value to the
real `WurmClientBase.setPassword(String)` before `launch`. The existing Steam shim
uses that same identity for its identity API and local ticket. No new identifier
is generated by the launcher, and the server performs its original hashing/checks.

The separate `setServerPassword("")` remains unchanged. This test is for an
unprotected local server. It does not configure a password-protected server or
take a real Steam account password. Identity remains persisted under the managed
client's private home. Existing offline opt-in, loopback/3724 enforcement and
corrupt-identity rejection apply. A new package has its own identity and storage;
existing character ownership/migration between preview packages is not qualified.

The only production launch behavior change is this credential assignment. Existing
Steam callbacks, POC/server checks, Java 17 login encoder, position and item SQLite
fixes, runtime/native source pins, graphics/input and crash capture are preserved.
UI/report text identifies the current experiment. The app logs only:

```text
[client] LOGIN_CREDENTIAL_READY source=persisted-local-identity serverPassword=empty; credential data omitted
```

The marker confirms assignment, not server acceptance. It omits identity, login
credential, hashes and ticket bytes. Existing connection/auth/login monitoring
and failure reporting remain the evidence for the subsequent result.

## Exactly what to install and import on the Thor

Install **Wurm-Server.apk** from **v0.10.14-local-login**. The APK includes the
managed ARM64 JVM, authored adapters and current graphics compatibility stack.
No external JVM installation or new native-library download is required.

Use the **same two ZIPs already successfully imported in 0.10.13**:

| Archive | Required existing contents |
| --- | --- |
| Prepared server runtime ZIP | `server.jar`, `common.jar`, `lib/`, `Adventure/` and its database/map/configuration files, and the existing `poc-lib/sqlite-jdbc-3.53.2.1.jar` plus `poc-lib/sqlite-jdbc-3.53.2.1-natives-android.jar`. Keep the complete prepared runtime layout and other existing files. The source-backed POC is supplied by the APK. |
| Complete owned client ZIP | `client.jar` and the rest of its client JARs/dependencies and assets, including the complete `packs/` directory (`graphics.jar`, `pmk.jar`, `sound.jar` and all other supplied packs), configuration/resources and other original client files. Keep the previously accepted directory layout; `client.jar` alone is insufficient. |

Do not extract archives manually, replace game JARs or copy files into app-private
directories. Select the existing archives through Android's document picker.
The separate package is `io.github.russianranger.wurmlauncher.loginidentity`
(version code 28). It preserves older versions' data and avoids debug-signature
replacement conflicts; it does require importing into this new app again.

## Physical-device test

1. Keep the old apps, original server archive and checkpoints. Stop the client
   and server in 0.10.13 and any older version before starting the new server.
2. Open **0.10.14 → Import Server ZIP**, choose the same prepared archive, and
   select **Adventure**. Wait for import validation to finish.
3. Open **Client tab → Import Client ZIP**, choose the same complete client
   archive, and wait for validation. Leave the player name **Thor**.
4. Choose **Start Local Game** in **0.10.14**. It starts this version's server,
   waits for `127.0.0.1:3724`, and launches the actual client. Do not launch an
   older server to supply the port. No Steam browser/account password is needed.
5. Let startup advance beyond authentication/login or show a failure. Startup
   has a five-minute limit; a detected game loop continues until Stop Client.
   If the world appears, test movement, look and clicks for about 60 seconds.
   Take a screenshot showing the resulting screen and status.
6. Stop Client if it is still active. Before Retry, use **Client tab → Export
   Client Report** and save as `wurm-client-0.10.14.txt`.
7. Stop Server if still running; wait for its result. Use **Server tab → Export
   session report** and save as `wurm-server-0.10.14.txt`. This is the **Session
   Report**, not Storage Report or World Report. Send both reports and screenshot.

No controller/triangle or JVM Memory Test repeat is needed for this credential
test. If the server reports `Address already in use`, stop the old server first.
If it reports a different login or database failure, retain that evidence; do not
erase the world or change passwords to work around it.

## Validation and remaining gates

Handwritten engine/ticket fixtures exercise the real DirectClientLaunch helper:
the credential must be nonempty and equal both the Steam identity API and ticket
identity. Tests launch repeatedly with the same private home, also change player
name, verify persisted identity and ensure output omits it. Nonlocal targets,
missing offline opt-in and corrupt identity must fail before engine launch.
Existing async/crash/resource tests remain active.

An optional private test uses the supplied server's original `raiseFirstLetter`,
`encrypt` and `hashPassword` bytecode, with the existing encoder overlay. For three
authored player inputs, an empty credential and a different identity do not match
the expected hash; the matching identity does. Only those methods are isolated
in temporary storage, with unchanged method bodies and an authored exception
stub. This is **not a full server login simulation**. No game code enters CI.

```sh
python3 -m unittest discover -s tests -v
# Optional local-only tests; files must be legally obtained:
WURM_TEST_SERVER_JAR=/absolute/path/server.jar \
WURM_TEST_SQLITE_JAR=/absolute/path/sqlite-jdbc-3.53.2.1.jar \
  python3 -m unittest discover -s tests -v
```

The full host suite has 109 tests; five private checks require the supplied server
JAR and skip in public CI. All Android variants must build, unit-test and lint
before publication. The developer-only real-client connection probe now supplies
the same identity for login; that probe was not rerun for this change because the
previously attached client JAR is unavailable in this workspace. The launch ABI
was previously verified and reached login on the Thor; no new game API is added.
